# AGENTS.md

Before making changes, read the relevant durable project state files:

- `PROJECT_BRIEF.md` for product intent
- `TODO.md` for current tasks
- `DECISIONS.md` for important decisions
- `DESIGN_SYSTEM.md` for documentation and CLI presentation rules
- the relevant canonical page under `../docs/` for architecture, workflows, handover guidance, templates, taxonomy, or other stable reference material

Do not rely on chat history as long-term memory. If a change affects project direction, architecture, design rules, active tasks, or important decisions, update the corresponding durable state file.

For small edits, read:
- `PROJECT_BRIEF.md`
- `DESIGN_SYSTEM.md`
- `TODO.md`
- the files being edited

For structural changes, also read `DECISIONS.md` and the relevant developer pages under `../docs/developer/`.

Do not duplicate stable guidance in `project_state/`. Update its canonical `docs/` page when architecture, successor workflows, maintenance guidance, templates, or rubrics change.

After meaningful changes, summarize:
- what changed
- files changed
- durable state files updated
- checks run
- next steps
